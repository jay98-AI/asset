## Exact-set rules

The validator requires every v1 requirement ID exactly once. It rejects empty, singleton, null, duplicate, unknown, malformed, and blank-evidence rows. Row order is intentionally ignored because coverage is an exact identity set; equality is meaningful only as a duplicate ID and fails. Adjacency is not applicable: requirement IDs are neither numeric intervals nor temporal boundaries, so rows cannot overlap or merge at an edge.
